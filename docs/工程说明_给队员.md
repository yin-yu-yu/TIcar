# 小车工程说明书（给队员）

> 看完这个文件，你就知道每个文件夹是干什么的，你的代码应该写在哪里。

---

## 一、这个工程是干嘛的

我们要做一辆比赛小车。小车上有一个 **MSPM0G3507 单片机**（相当于小车的大脑），它负责：

1. 读取传感器（红外循迹、编码器测速、陀螺仪测角度）
2. 根据当前状态做出决策（前进、转弯、停车）
3. 控制电机转动
4. 通过蓝牙和手机 APP 通信

整个工程就是把上面这些事情写成 C 语言代码，烧录到单片机里运行。

## 二、文件夹是什么意思

你把工程想象成一栋 **四层楼的房子**，每一层干不同的事：

```
┌──────────────────────────────────────┐
│  4楼 Application/    应用层          │  ← 决策大脑（队长写状态机）
│     决定"小车现在该干什么"            │
├──────────────────────────────────────┤
│  3楼 Middleware/     中间层          │  ← 算法工具（PID、运动学、滤波）
│     提供"怎么算"的工具函数            │
├──────────────────────────────────────┤
│  2楼 Hardware/       硬件层          │  ← 驱动代码（你写的模块在这里）
│     直接操作芯片引脚和传感器          │
├──────────────────────────────────────┤
│  1楼 Debug/          系统层          │  ← SysConfig 自动生成
│     芯片上电后最先运行的初始化代码     │     （可以改）
└──────────────────────────────────────┘
```

**规则只有一条：上层可以调用下层，下层不能调用上层。**

就像 4 楼的人可以下楼找 2 楼要东西，但 2 楼的人不能直接跑上 4 楼。

## 三、每个文件夹里有什么

### 📁 `Config/` — 参数配置

**你只需要改这里的数字，不需要改代码逻辑。**

| 文件 | 里面是什么 | 你什么时候改 |
|------|-----------|-------------|
| `robot_config.h` | 小车轮子多大、轮距多宽、电池几伏报警 | 换了轮子/电池规格不同时改 |
| `pid_config.h` | PID 控制器的 P、I、D 参数 | 调 PID 时改（可以先用默认值） |

### 📁 `Hardware/` — 硬件驱动层（你的模块主要在这里）

**每一个 .c/.h 文件对应一个硬件模块。** `.h` 是说明书（声明有哪些函数），`.c` 是实现（具体怎么干活）。

| 文件 | 对应硬件 | 状态 | 说明 |
|------|---------|------|------|
| `motor.c/h` | 两个直流电机 | ✅ 已有 | 控制电机正反转和转速 |
| `encoder.c/h` | 两个编码器 | ✅ 已有 | 测量电机转了多少圈（算速度） |
| `IR_Module.c/h` | 4 个红外传感器 | ✅ 已有 | 检测地上黑线 |
| `mpu6050.c/h` | MPU6050 陀螺仪 | ❌ 空的 | **等你移植，目前是空壳** |
| `uart_bt.c/h` | 蓝牙模块 (HC-05) | ✅ 已有 | 和手机 APP 通信 |
| `uart_debug.c/h` | USB 转串口 | ✅ 已有 | 调试时往电脑打印信息 |
| `adc.c/h` | 电池电压检测 | ✅ 已有 | 读电池还剩多少电 |
| `oled.c/h` | OLED 小屏幕 | ✅ 已有 | 显示状态信息 |
| `key.c/h` | 按键 | ✅ 已有 | 检测按下/双击/长按 |
| `led.c/h` | LED 灯 | ✅ 已有 | 指示灯 |
| `board.c/h` | 系统杂项 | ✅ 已有 | 延时函数、打印函数 |

### 📁 `Middleware/` — 算法工具箱

**这里面的代码不涉及具体硬件，只做数学计算。**

| 文件 | 干什么用 | 例子 |
|------|---------|------|
| `pid.c/h` | PID 控制器 | 输入"目标速度"和"实际速度"，输出"该给多少油门" |
| `kinematics.c/h` | 运动学计算 | 输入"想往前 0.3m/s + 往左转 0.5rad/s"，输出"左轮多少速度、右轮多少速度" |
| `odometry.c/h` | 里程计 | 根据编码器数据推算小车当前位置 (x, y, 角度) |
| `filter.c/h` | 滤波器 | 把有噪声的传感器数据变平滑 |

### 📁 `Application/` — 应用层（队长主场）

| 文件 | 干什么用 | 负责人 |
|------|---------|--------|
| `state_machine.c/h` | **状态机**：决定小车当前处于什么状态（待命/遥控/巡线/低电量/故障） | **队长** |
| `motion_control.c/h` | 运动控制：把目标速度变成电机的 PWM 输出 | 队员 |
| `line_follow.c/h` | 巡线策略：读红外传感器，算该怎么转弯 | 队员 |
| `bt_protocol.c/h` | 蓝牙协议：解析手机 APP 发来的指令 | 队员 |
| `debug_scope.c/h` | 虚拟示波器：调试时把变量波形发到电脑上看 | 调试用 |

### 📁 `Control/` — 旧代码（不要删，暂时保留）

这里面的代码是 WheelTec 原厂的，功能是对的但写法比较乱。**最终要逐步迁移到上面的新架构中。** 你暂时不用管。

### 📁 `Debug/` — 系统自动生成的文件

**千万别手动改！** 这是 SysConfig 工具根据 `empty.syscfg` 自动生成的。如果你改了会被覆盖掉。

里面最重要两个文件：
- `ti_msp_dl_config.h` — 定义了每个引脚、每个外设叫啥名字
- `ti_msp_dl_config.c` — 芯片上电时的初始化代码

### 📁 `docs/` — 文档

| 文件 | 内容 |
|------|------|
| `工程说明_给队员.md` | 就是你正在看的这个 |
| `CHASSIS_API.md` | 所有函数的详细说明书（英文，给 AI agent 看） |

## 四、你的代码应该写在哪里

### 如果你是负责移植 MPU6050 的

1. 打开 `Hardware/mpu6050.c`
2. 找到 `TODO` 标记的地方
3. 把你的 I2C 初始化和 DMP 驱动代码填进去
4. 接口（函数名和参数）已经写好了在 `Hardware/mpu6050.h` 中，照着实现就行
5. **不要改 `.h` 文件的函数签名**，否则别人调不了

### 如果你是负责电机/编码器的

- 代码已经在 `Hardware/motor.c` 和 `Hardware/encoder.c` 里
- 你的任务是：验证方向对不对、有没有死区、参数配没配对
- 调整 `Config/robot_config.h` 中的机械参数

### 如果你是负责巡线策略的

- 旧代码在 `Hardware/IR_Module.c`，新接口在 `Application/line_follow.c`
- 你的任务是把旧代码的逻辑理解后迁移到新的 `line_follow.c` 中
- 可调参数放到 `Config/robot_config.h`

### 如果你是负责蓝牙协议的

- 旧代码在 `Control/uart_callback.c`，新接口在 `Application/bt_protocol.c`
- 你的任务是迁移协议解析逻辑

## 五、怎么调试你的代码

工程支持两种模式，在 `empty.c` 第 15 行：

```c
#define CHASSIS_DEBUG    // 取消注释 = 调试模式
```

### 调试模式

取消注释后，程序会进入调试循环。你在下面找到对应位置，加上你自己的测试代码：

```c
// [Member-A] 电机测试:
Motor_SetPWM(2000, 2000);   // 前进
delay_ms(500);
Motor_Stop();               // 停止
delay_ms(500);

// [Member-B] IR 传感器测试:
uint8_t ir = IR_GetSensorState();
OLED_ShowNumber(0, 20, ir, 1, 12);   // 显示在 OLED 上

// [Member-D] MPU6050 测试:
if (MPU6050_DataReady()) {
    float yaw = MPU6050_GetYaw();
    Debug_Printf("Yaw=%.1f\r\n", yaw);   // 打印到电脑串口
}
```

**好处：** 每个人在调试循环里加自己的测试代码，不影响别人的模块。也不会破坏比赛模式的主逻辑。

### 比赛模式

把 `#define CHASSIS_DEBUG` 重新注释掉，编译出来的就是完整的状态机比赛程序。

## 六、常见问题

### Q: `.h` 和 `.c` 有什么区别？

| | `.h` (头文件) | `.c` (源文件) |
|---|---|---|
| 作用 | 声明"有这个函数" | 实现"这个函数怎么干活" |
| 给谁看 | 给调用者看 | 给编译器看 |
| 类比 | 菜单 | 厨房 |

### Q: `#include` 是干什么的？

就是把另一个文件的内容"粘贴"到当前文件。比如你在 `line_follow.c` 里写了 `#include "ir_track.h"`，就可以调用 `ir_track.h` 里声明的函数了。

### Q: 我该 `#include` 什么？

最简单的办法：在你自己写的 `.c` 文件最开头写一行 `#include "board.h"`，就能用几乎所有功能了。

### Q: 不会改引脚怎么办？

打开 `empty.syscfg`（用 CCS 打开，会启动 SysConfig 图形界面），在图形界面里拖拽配置引脚，点保存，`Debug/ti_msp_dl_config.c/h` 会自动更新。不需要手写寄存器代码。

### Q: `extern` 是什么意思？

表示"这个变量在别的 `.c` 文件里定义的，我这里只是借用一下"。比如 `extern int Flag_Stop;` 意思是 `Flag_Stop` 这个变量在别处，你别重复定义。

### Q: 报错了怎么办？

1. 先看错误提示在哪个文件的哪一行
2. 常见原因：拼写错误、忘写分号、括号不匹配、变量没定义
3. 把错误信息复制给你的 AI agent，让它帮你分析
